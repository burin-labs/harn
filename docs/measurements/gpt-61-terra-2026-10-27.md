# GPT-6.1 Terra capability observations

Observed 2026-10-27 against the live provider APIs. These are smoke checks,
not a quality benchmark or a claim that every provider feature works.

| Route | Observed behavior |
| --- | --- |
| OpenAI `gpt-6.1-terra` | All six efforts returned the correct arithmetic answer and echoed the requested effort. A forced function call and its unique tool-result receipt completed. Strict JSON, streamed text with a completion event, and 256px red/blue image controls passed. |
| OpenRouter `openai/gpt-6.1-terra` | All six efforts, function/result round trip, strict JSON, streaming with a terminal event, and red/blue image controls passed. `none` reported zero reasoning tokens. |
| Vercel `openai/gpt-6.1-terra` | Function/result round trip, strict JSON, streaming and red/blue image controls passed. Scalar effort values were accepted; an invalid effort was rejected. Both scalar and nested `none` still reported reasoning tokens, so the registration excludes explicit off/none. |
| OpenRouter `openai/gpt-6.1-terra-pro` | All five reasoning efforts, a function/result round trip, strict JSON with a schema-only nonce, and red/blue image controls passed. Disabling reasoning returned the expected HTTP 400. |
| Vercel `openai/gpt-6.1-terra-fast` | All five reasoning efforts, a function/result round trip, strict JSON with a schema-only nonce, and red/blue image controls passed. |

Direct Responses requests echoed Fast, Flex and Pro mode. A repeated direct
prompt produced a measured cache hit of 2,530 input tokens after a zero-hit
control. Both gateway base routes also produced 2,530-token cache hits after
zero-hit controls. No throughput multiplier was measured or copied from another model.

Direct Chat Completions accepted a native function call at effort `none` and
rejected tools at effort `low`, advising the Responses API. The registration
therefore requires Responses when combining reasoning and tools. The model
documentation's blanket tool restriction is broader than this observation.

A 32px solid-red image returned `pink`. Larger red and blue controls passed.
This failed smoke remains part of the evidence; it is not evidence that vision
is unavailable, nor a visual-reasoning quality measurement.

## Catalog facts and limits

- [OpenAI model documentation](https://developers.openai.com/api/docs/models/gpt-6.1-terra)
  and [pricing](https://developers.openai.com/api/docs/pricing) supplied the
  context window, token rates and service modes.
- [OpenRouter model index](https://openrouter.ai/api/v1/models) and
  [Vercel model index](https://ai-gateway.vercel.sh/v1/models) confirmed the
  served gateway variants, context windows and route-specific prices.
- Long-context bands are declared prices, not measured million-token calls.
  Cache prices are published facts; all three base routes produced positive
  cache-hit probes. Regional Vercel requests cost 10% more than the
  global route; regional routing is not represented by these global rows.
- Batch aliases in the OpenRouter index describe asynchronous transport, not
  additional interactive model choices. This registration does not claim a
  newly verified Batch workflow.

## Canonical runtime

The built Harn CLI reached the real provider adapters, request builders and
native tool parser on all five routes at effort `low`. Each route passed one
non-streaming and one streaming `provider tool-probe` case, each with exactly
one parsed native call and reported token usage. The captured requests select
OpenAI Responses, OpenRouter's nested `reasoning.effort=low`, and Vercel's scalar
`reasoning_effort=low` without nested reasoning. Only the generation default was
set in a temporary user config; provider capabilities and endpoints were not
overridden. This is an adapter/parser smoke, not a full Burin agent turn.

Four earlier default-effort calls passed on OpenAI and OpenRouter. The probe
initially expected an explicit effort even when the catalog leaves it unset;
that offline assertion was corrected before testing the remaining routes.
The explicit-effort sweep used a separate receipt and reused no live result
from the default-effort calls.

## Spend

The 78 raw API requests included 75 successful responses with usage and three
expected HTTP 400 controls. Gateway `usage.cost` totaled $0.0365255.
OpenAI token usage at the published standard/Fast/Flex rates, including cache
writes, estimated $0.0077715. The 14 canonical runtime calls added $0.005154 in
Harn-priced usage. Across raw and canonical probes, 92 requests produced 89
successful responses and three expected HTTP 400 controls, with no missing
successful usage. Combined reported and estimated probe spend was **$0.049451**.
These measurements are not an invoice or an account-wide spend read; review
spend is separate.

## Registry workflow

Before this change, the same addition required model rows, capability fragments,
an alias table and family-picker values, followed by three generation targets.
The new `registration` entry generates those projections with one command.
Terra also removes three obsolete replacement pointers from older rows once;
subsequent model additions do not need to maintain those parallel pointers.
The generator fixture adds one source file, verifies its exported routes,
request contrast, alias and picker, then rejects a corrupted generated artifact.

A second fixture appends one successor registration whose ID sorts before its
predecessor. It initially failed because the generated gateway route did not yet
exist, then exposed a duplicate alias when the successor reused a public name.
The corrected lowering builds all rows first and settles predecessors before
successors. The fixture now replaces both route pointers, reuses the aliases,
and keeps the picker slot in place without editing the old registration.
An unrelated model attempting to take the same picker value is rejected.
