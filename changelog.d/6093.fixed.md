Reject unknown capability roots on `Harness` at check time instead of deferring
every miss to the VM. `harness.crypto.sha256(...)` previously passed `harn
check`, `harn lint`, `harn fmt --check`, and a full package test suite, then
raised a hard runtime `TypeError` on the first path that executed it — in one
case 46 minutes into a live release, after the release commit had already been
built, signed, and pushed. The checker now names the closed capability set from
the same `CapabilityId` registry the runtime enumerates, and suggests the
closest root for a near miss. Optional access (`harness?.missing`) stays
gradual, because the VM answers it with `nil` rather than an error.
