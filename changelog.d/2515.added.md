- **Transport-completeness primitives for `harn-serve` (#2515).** Every
  HTTP adapter (API, A2A, MCP) now layers response compression
  (gzip/brotli/zstd via `Accept-Encoding` negotiation), strong-ETag
  conditional GETs (`If-None-Match` short-circuits to `304 Not
  Modified` for JSON responses), and optional declarative CORS through
  a single `TransportConfig`. Two new `.harn` builtins —
  `http_etag(body) -> string` for handler-side strong-tag computation
  and `http_choose(accept, candidates) -> string?` for RFC 9110 content
  negotiation — let handlers cooperate with the middleware (or
  implement these semantics themselves on bespoke routes). The
  ETag/compression layers compose so the digest is stable across
  `Accept-Encoding` negotiation. WebSocket upgrade, multipart streaming,
  chunked-request streaming, and HTTP/2 server push are tracked
  separately; they need request-context plumbing into `.harn` handlers
  that doesn't exist yet.
