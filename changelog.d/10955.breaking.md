- **Replay and eval verdicts never compare a run with itself (#10955).**
  `harn replay`, `harn eval`, eval suites, eval packs and the `run_record_eval`
  builtins check a run only against a fixture independent of it, and fail a
  verdict that compared nothing. The fixture Harn records when it saves a run
  is the reference for other runs of that workflow; checked against the run it
  came from, it reports `checked: false` instead of a pass. A run record with
  no fixture fails. Replay traces get the replay oracle's verdict on both
  recorded executions. A single replay read with no verdict, including one of
  a session rebuilt from its own events, exits 2 with
  `error.code: "replay_not_checked"`. Files whose `_type` is not `run_record`
  are refused.

  Migration: Rust consumers constructing `ReplayEvalReport` must set `checked`
  and `expectations_compared`, and those constructing `ReplayOracleReport` must
  set `compared_values`; spread `..Default::default()` where nothing was
  compared. To check a run, evaluate it against a fixture recorded from a
  different run, or a hand-written fixture with an expectation and no
  `source_run_id` of its own. Scripts that treated exit 0 from a single
  `harn replay --session-id` read as success should pass `--runs 2` or read
  the `replay_not_checked` code.
