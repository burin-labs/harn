`harn fix --capability-migrations-only` now names the callable that blocked a
capability migration. A callable whose value is read as a first-class reference
keeps its arity, which is correct — it is invoked through a call site no static
pass can see. But when that callable also owns the ambient capability use, its
missing parameter edit discarded the whole file's repair, and the run reported
`applied 0 repair(s), skipped 0` and exited 0 with the capability diagnostics
still standing. Nothing said which callable was responsible or how to unblock
it. Plan and apply now both report the frozen callables, and `--json` carries
them under `frozenCallables` (omitted when empty).
