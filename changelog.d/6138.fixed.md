`harn fix --capability-migrations-only` no longer rewrites a callable that the
program names as a value. A function used as a value carries a declared function
type at that site — most often a typed parameter default such as
`resolver: ResolverFn = resolve_thing` — so prepending a capability parameter or
narrowing an existing `Harness` changed its type and left the migrated tree
failing to compile with an arity mismatch reported in a file the migration never
mentioned. Both repair paths now treat such a callable's signature as frozen:
the per-file threading pass declines the repair, and the whole-program planner
stops with a message that names the callable and the remedy.
