- **A rate card can now express recurring time-of-day windows and a one-hour
  cache-write tier, and every call settles at the instant it started
  (#8557).** DeepSeek bills weekday peak hours at double its off-peak rate and
  Anthropic bills a one-hour cache write above a five-minute one; neither was
  expressible, so a DeepSeek route over-billed every off-peak call by 2x and a
  one-hour write settled 1.6x under. `ModelPricing` gains `schedules`, a list
  of recurring windows with a fixed UTC offset that multiply the base card,
  and `cache_write_1h_per_mtok`, selected by the lifetime the request already
  asks for. Overlapping windows are a catalog validation error, compared on
  minutes-of-week in UTC so two windows authored in different offsets still
  collide. Settlement no longer resolves the card at catalog read time: the
  call's start instant travels on its telemetry, so a promotion that expired
  mid-session stops applying at its own instant rather than at the next
  catalog load, and a recorded run re-prices at the card that was in force
  while it ran. The receipt, the VM usage ledger and the `cost_usd` span now
  carry `rate_card` (`base`, `promotion:<id>` or `schedule:<id>`) with the
  input band, the serving tier, and `cache_ttl_unpriced` when a route
  publishes no rate for the lifetime that was asked for. Provider catalog
  schema 12; consumers must regenerate their bindings.
