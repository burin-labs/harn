- `harn-rules` patterns gained **typed placeholders** `$VAR:kind` (Rule Engine Epic A, rust-analyzer SSR style) — a
  metavariable can be constrained to a syntactic class, so `log($ARG:identifier)` matches `log(x)` but not `log(f())`.
  `:kind` is a semantic alias (`expr`/`expression`, `stmt`/`statement`, `ty`/`type`, `ident`/`identifier`, resolved to
  the target grammar's supertype) or an exact tree-sitter node kind; the constraint lowers a `(_)` wildcard capture to
  `(kind)`. A constraint that names no kind in the grammar is a compile error (the supertype aliases exist in
  TypeScript/JS/Python but not Rust/Go, where exact kinds are used). Works through the full declarative path —
  `pattern = "..."` in a rule's TOML, and thus `rules.search` / `rules.apply` from Harn.
