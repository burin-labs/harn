- `harn run` gains a session credential posture: `--capability-profile
  <hermetic|lane>` and repeatable `--grant NAME=SOURCE[,expose=ENV_VAR]` (#4992).
  A hermetic run closes the subprocess environment to a fixed allowlist; a lane
  run admits exactly the declared grants (an `env:VAR` launcher snapshot or a
  `secret://ACCOUNT/KEY` pointer), optionally exposed to spawned commands as an
  environment variable. This is the launcher surface for session-scoped
  capability grants (the runtime landed in #5011): a headless lane can now hand a
  subprocess a scoped `GH_TOKEN` to open its PR without leaking every other
  ambient credential. Grants are disclosed on stderr and receipted under
  `--attest`; both flags conflict with `--no-sandbox`.
- A capability profile now governs harn's own credential lookup, not just the
  environment handed to spawned subprocesses. Under `--capability-profile
  hermetic` a run cannot reach a provider key the operator happened to export,
  which is what makes an eval reproducible rather than dependent on the
  launcher's shell; under a lane, a granted key is usable by that run's own
  `llm_call`. Runs that select no profile are unchanged.
- `--grant provider:PROVIDER` grants a model credential using the variable name
  from the provider catalog, so a launch script no longer restates a mapping the
  catalog already owns. It selects the same variable dispatch would, and keeps
  working when a provider adds or renames one.
- `harn time run` now accepts every confinement and credential flag `harn run`
  accepts, including `--capability-profile` and `--grant`. Both commands share
  one flag definition, so a run and its timed twin can no longer drift apart.
- An exported-but-empty provider auth variable is now treated as a missing
  credential rather than resolving to an empty key. Providers declaring several
  auth variables already behaved this way.
