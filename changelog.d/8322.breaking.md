The runtime configuration document no longer carries `limits`, `permissions` or
`policy` sections. No run ever read them, so a budget, permission default or
locked field set there had no effect and produced no diagnostic, which made an
ignored setting indistinguishable from an honoured one. A configuration file
that still declares one of the three is now refused by name at the parse
boundary, and the six environment variables that wrote into them
(`HARN_BUDGET_USD`, `HARN_TOKEN_BUDGET`, `HARN_MAX_CONCURRENCY`,
`HARN_NETWORK_MODE`, `HARN_FILESYSTEM_MODE` and `HARN_SANDBOX_MODE`) are no
longer registered, so setting one stops startup with the usual unknown-name
diagnostic. Run cost and token ceilings live in the agent budget mechanism, and
capability permission lives in the per-run security policy surface, both of
which runs do consult. The config explain output loses its locked and denied
columns with the mechanism that filled them.
