The branch-comparison guards now fail when they cannot read the base revision,
instead of exiting clean. `git show <unfetched-commit>:<path>` reports the same
"exists on disk, but not in ..." wording as a path that genuinely was not in the
tree, so an unreadable base was indistinguishable from a branch that removed
nothing — and the second reading is the one that passes. Both
`check-changelog-no-retroactive-edits` and the new
`check-protocol-symbol-removals` now resolve the base to a commit first, print a
scope line naming the resolved commit and what they compared, and exit non-zero
with the remedy when they could not compare.
