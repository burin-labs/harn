A type annotation no longer silences `HARN-OWN-004` under `--strict-types`.

The rule enforces validate-once-at-the-owning-boundary, and it offered three
remedies. Two of them check something; the third did not. A type annotation is
erased before the value exists, so

```harn
const doc: {name?: string} = json_parse("{\"name\": 12345}")
```

reads an `int` out of a field declared `string`, and `json_parse("[1,2,3]")`
satisfies a record annotation — neither diagnosed at compile time or at run
time. Annotating a parse result cleared the diagnostic and added no safety, and
because a one-line annotation is far less work than writing a schema, the help
text steered readers toward the one remedy that removed the signal.

`schema_expect()` and `schema_is()` in an if-condition still clear the mark,
because they validate. The help text now says why an annotation does not.

This can newly report `HARN-OWN-004` on code that annotated a boundary value to
satisfy the checker. Those sites were never validated; replace the annotation
with `schema_expect()` or a `schema_is()` guard.
