The missing-tool-call corrective now tells the model which arguments the call
must carry, instead of showing an empty argument object and asking it to "fill
in the arguments" it had never been shown. The names come from the tool entry's
declared parameters, via `tool_required_argument_names` beside the existing
parameter readers that already own shape tolerance for JSON-schema
`properties`/`required` and the flat `{name: schema}` form. The corrective does
not hand-write argument shapes, so there is one owner of that policy rather than
two.

The names are said in prose, after the rendered call, rather than shown as
values inside it. An intermediate version rendered a type placeholder per
argument (`edit({ path: "<string>" })`) on the theory that a model copying it
verbatim would produce an obviously unfilled call; a live run showed it copy
that token into every call for the rest of the session instead.

Measured motivation: on an embedder's local-model lane the corrective converted
0 of 70 claims into a tool call on the following turn, with nine of thirteen
runs producing no tool call at all after it first fired. This change is the
first and cheapest suspect for that; it is not yet shown to move the conversion
rate.
