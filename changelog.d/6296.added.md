Connector service operations can now declare the arguments they accept, under
`[[providers.service.operations.parameters]]`. Each parameter carries a name, a
model-facing description, a type from a closed vocabulary, whether it is
required, and an optional closed set of allowed values. This is what lets a host
project a connector operation into an agent tool without hand-writing an
argument table per connector. Declaring parameters is optional and existing
manifests stay valid.
