Workflow stage compaction options were written where the agent loop never read
them, so tier-2 compaction on workflow stages now applies. A stage that
configured `hard_limit_tokens`, `hard_limit_strategy`, `tool_output_max_chars`
or a summarize prompt had those values placed alongside `auto_compact` rather
than inside it, and the agent loop lifts only four sibling keys into its
compaction options. Every other one was discarded in silence, so a stage asking
for an LLM summary at the hard limit ran on the engine defaults instead. Stages
that already set these values will see their configured tier-2 behavior for the
first time. `compress_callback` and `mask_callback` are no longer forwarded from
a stage: they are read by `agent_session_compact`, never by the compaction path
an agent loop takes, so forwarding them only ever produced a key nothing on that
path could read.
