# Missing tool-call decision cutover

The decision-backed classifier preserves recovery on the fresh 12-text corpus
and repairs the structured route's four misses in the development pilot.
Native decisions are faster and cheaper in this measurement. The structured
fallback costs more, and native confidence withheld one intended edit in the
development follow-up. The consumer's confidence floor remains `0.65`.

## Method and identity

The holdout contains six intended calls and six negatives, with four texts each
in English, Spanish, and French. It was committed before the first v6 call.
Each text ran five times in three rotating arms, for 180 completing runs.
Primary assistant turns and tool execution were replayed; classification used
live providers through the canonical `agent_loop` and classifier. This measures
classifier and recovery-nudge fidelity, not a live primary agent's success rate.

The legacy classifier and prompt were extracted unchanged from current-main
revision `ae55458b682edba14ecf20c3b67f5f19c9ef05eb`. Both chat arms used direct
OpenAI GPT-5.4 nano with effort `none`, temperature `0.0`, and an output cap of
`192`. Native used the catalog's OpenRouter Jev 1.13 decision route, with
conservative budget authority installed before dispatch. All arms received the
same assistant text and candidate tools, including the loop's resumption tool.
The loop's existing terminal-classifier skip rules remain in force.

The tested source revision was `51a7f1836991c6c58e53c43ffbbca71da0fbbd22`, with
structured instruction version `harn.evaluator.structured.v6`. The
[manifest](cutover-v6-manifest.json) pins the source, corpus, prompts, replay,
baseline, routes, and immutable executable SHA-256. The executable was copied
after its runtime build; its CLI provenance relink was deferred until reporting
finished. No runtime source changed during the study. The new evaluator reported
served models `gpt-5.4-nano-2026-03-17` and `typesafe/jev-1.13-20260917`.
The legacy checkpoint exposes its requested alias, not a served revision.

## Completing-run measurements

Every run completed, emitted one recovery verdict, and made one physical
classifier request. There were no failed requests or missing cost records in
this study. Classifier cost reconciled with completing-run cost and, for the new
arms, the evaluator receipt. Replayed primary execution incurred no API cost.

| Arm | Correct recovery and positive tool | False / missed recovery | Classifier median | Run median | Mean cost per completing run |
| --- | --- | --- | --- | --- | --- |
| Legacy structured | 60/60 | 0 / 0 | 1,720 ms | 2,632.5 ms | $0.000169421 |
| Structured decision | 60/60 | 0 / 0 | 1,714.5 ms | 2,574 ms | $0.000288188 |
| Native decision | 60/60 | 0 / 0 | 261 ms | 1,150 ms | $0.000030020 |

Native's mean cost was 82.3% lower than legacy; structured's was 70.1% higher.
The paired mean classifier-latency difference was -1,657.1 ms for native
(row-cluster bootstrap 95% interval -1,775.9 to -1,545.9 ms), and +61.25 ms for
structured (-65.0 to +166.4 ms). These intervals describe the twelve sampled
texts; repeats do not create sixty independent examples.

Both new backends agreed on recovery in 60/60 pairs. They agreed on the exact
verdict action in 55/60: structured returned `ambiguous` on five negative
trials, where native returned a confident negative. Both recovered in 30 pairs
and chose the same tool in all 30. Non-recovery pairs do not count as tool
agreement. All arms matched recovery labels on 20/20 trials in each language.

Both chat arms reported cache reads for 60/60 requests, all zero. Native cache
accounting was unavailable for 60/60 requests; runtime placeholder zeros are
not evidence of measured cache misses. Physical requests were still observed
for all 180 runs. Full metrics and compact actual observations are in
[analysis](cutover-v6-analysis.json) and
[observations](cutover-v6-observations.jsonl).

## Calibration and limits

The owning `std/eval/calibration.calibration_report` consumed 270 labeled
question rows: 60 intent answers and 30 positive-target answers per arm. It
reports confidence bins and threshold results at `0.0`, `0.65`, and `0.9` in
[the calibration report](cutover-v6-calibration.json).

| Arm | Intent correct / scored | Intent accepted at 0.65 | Intent calibration error | Positive tool correct / scored | Tool calibration error |
| --- | --- | --- | --- | --- | --- |
| Legacy structured | 60/60 | 60/60 | 0.109000 | 30/30 | 0.160000 |
| Structured decision | 60/60 | 55/60 | 0.128167 | 30/30 | 0.120334 |
| Native decision | 60/60 | 60/60 | 0.102833 | 30/30 | 0.000000 |

Five correct structured negative answers had confidence below the consumer
floor; withholding them did not change recovery. Every positive tool answer
met the floor. Native boolean confidence derives from its returned probability;
choice confidence derives from its distribution. Chat confidence is
self-reported. Equal thresholds do not establish equal error rates.

This curated corpus is descriptive evidence, not a deployment accuracy or
calibration guarantee. Ignore generated threshold recommendations: repeats of
twelve texts do not meet an independent, exchangeable-sample assumption. No
threshold was selected from this report.

## Development failures and follow-up

The [v5 pilot](cutover-v5-pilot-analysis.json) completed 36 runs. Legacy and
native matched recovery on 12/12 texts; structured matched 8/12, missing four
positive intents. Actual request and response inspection showed question
instructions only in schema descriptions. Explicit true/false criteria in the
schema did not repair the failing edit example. A controlled placement probe
with the same schema succeeded when question descriptions appeared in the user
prompt. Production v6 derives those descriptions from the schema and renders
them through the canonical prompt engine, including choice meanings and score
levels. It keeps the original consumer questions and thresholds.

The [v6 follow-up](cutover-v6-regression-analysis.json) reran those twelve texts
once per arm. Legacy and structured matched recovery on 12/12; native matched
11/12. For `fr-edit-now`, native answered true and selected `edit`, but returned
intent probability `0.63`, below `0.65`. It therefore withheld the recovery
nudge. The text had no typo. This observed abstention remains in the
[observations](cutover-v6-regression-observations.jsonl),
[calibration](cutover-v6-regression-calibration.json), and
[manifest](cutover-v6-regression-manifest.json). It is not a reason to lower the
floor using development data.

The earlier archived September studies remain in [the experiment history](README.md).
A separate attempted v5 repeated study stopped after 24 recorded runs when a
baseline stream ended early. The old instrument confused checkpoint attempts
with physical provider dispatch. The reusable runner now reads provider-call
counts, preserves unknown cost, and refuses to count missing usage as free.
A Vercel native pilot returned HTTP 403 with unavailable usage; OpenRouter was
the reachable native route used for the completed studies. These failed
requests were not silently retried or included as successful quality trials.

The 180-run holdout cost $0.029257670; the 36-run v6 follow-up cost $0.005788042;
the 36-run v5 pilot cost $0.005263642. Completed-study spend was $0.040309354.
Instrument pilots and placement probes are additional; two failed provider
requests lacked usage. Their absence is not a measured zero.

## Deterministic product evidence

The rebuilt CLI rejects misspelled callback failure fields and missing cause
halves while accepting callback, dispatch, and cancellation records. The actual
loop preserves both callback causes and refuses an empty request before provider
dispatch. Malformed evaluation consumes one request, returns refused, injects
no recovery nudge, and lets the loop complete; cancellation propagates.

Typed fixtures exercise both backends with opaque text. Removing the fixture
makes the positive assertion fail. Physical mock requests prove chat overrides
and question delivery, including choice meanings and score levels. The archived
instruction-budget control refuses long question instructions with zero
dispatch and reaches one request for the short control. Analyzer controls cover
zero eligible agreement pairs, a measured match, a mismatch, and unavailable
cost and cache accounting. Harn lint, formatting, docs snippets, source drift,
and tree-sitter checks passed against their owning paths.

Review found that automatic native routing dropped explicit chat overrides.
The correction forwards all six settings so the evaluator refuses them without
dispatch. The regression fails on the measured CLI with `admission_refused`
instead of `unsupported_options`. The measured native profile used an explicit
evaluation policy without chat settings; the structured profile retains the
same defaults and overrides. Those study inputs are unchanged, so the live
measurements carry forward.

`run-cutover.mjs` reproduces the three-arm comparison. Its optional final
argument selects the corpus filename; `analyze.mjs` requires every expected
study cell before producing a report. The host restart removed the temporary
raw run receipts and request tapes in `/tmp/harn-8521-8543.iOfWt5`. Committed
manifests and observations preserve the measured identity and outcomes without
credentials; the original temporary traces are no longer available.
